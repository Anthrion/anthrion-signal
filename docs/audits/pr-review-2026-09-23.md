## Blocking findings

### PR 22: revision ordering changes source facts (high)

`normalise_ted` changes both `published_at` and `updated_at` from the source day's
Brussels-midnight instant to a date interpreted at UTC midnight. `dedupe.merge`
still compares `updated_at` instants to choose the authoritative revision.

Reproduction: a TED notice dated `2026-07-02+02:00` followed by a linked German
cancellation at `2026-07-01T23:30:00+00:00`. Main accepts the cancellation, which is
later than the TED instant (`22:00 UTC`). The PR treats the TED date as `00:00 UTC`
and discards the cancellation as older. A presentation correction must not leave
a cancelled notice active. The description acknowledges changed ordering but does
not address this lifecycle consequence.

### PR 22: the migration infers date precision too broadly (medium)

`migrate_ted_calendar_days` runs for newly constructed signals as well as retained
JSON. An explicit TED timestamp `2026-07-02T00:00:00+02:00` becomes `2026-07-02`,
contradicting the claimed preservation of real clock times.

The fallback is also not restricted to TED-only lineage: a mixed German/TED
record with German publication time `2026-06-30T10:15:00+00:00` and a German
revision at `2026-07-05T22:00:00+00:00` gets its revision rewritten to `2026-07-06`.
Only other sources' *publication* times are protected, not their revision times.

All three independent date probes fail on the PR and pass without it. Future work
should separate displayed calendar precision from revision ordering, preserve
explicit instants, and restrict retained repairs to evidence proving their origin.
Do not infer precision merely from an instant landing at midnight.

### PR 23: formatting changes invalidate reviewed decisions (high)

Normalising the changed description updates the review source hash and translation
keys. Matching recommendations disappear and exclusions stop applying until
re-reviewed. The PR explicitly acknowledges this but does not supply the migration
or re-review. Routine Scotland recollection is sufficient to trigger it; avoiding
an explicit repair does not avoid the regression.

An independent scan of the current retained public snapshot found 671 records with
the relevant formatting patterns, including **135 active guidance decisions and
40 active exclusions**. This is a pattern-based affected-record audit, not a claim
that every retained source can be reconstructed exactly. Hash invalidation remains
the correct safeguard; do not bypass it or refresh review hashes automatically.

The Python search index retains lot identifiers, but `app/src/lib.ts:prepareSearch`
does not read structured lot IDs for full historical records. Removing their
description labels therefore removes previously searchable identifiers from award
and history views. A completed repair needs both search paths and proof-based,
reviewed handling of affected retained content.

### PR 25: an unchanged head does not prove a lookback was collected (medium)

The new `reread` flag is set from an unchanged head plus an empty/all-reread queue.
There is no persisted evidence of how far back successful coverage extends.

Reproduction: finish a seven-day initial walk; then request a fourteen-day replay
after a vocabulary change, with a two-page run budget. The PR reports `complete`
and “PLACSP is current” even though the added older week has never been collected.
The independent probe passes on main and fails on the PR. Pending work therefore
continues to report partial coverage in the selected follow-up.

Raising Spain's budget from three to eight pages is a separate runtime/bandwidth
tradeoff, not a free optimisation. It is omitted. The PR's exact drain-time and
bandwidth forecasts rely on its historical measurements and simulations; they
were not independently reproduced or adopted as operational guarantees here.

## Accepted changes and verification

### CSS

An independent TypeScript AST inventory covered class-producing expressions,
forwarded class props, DOM assignments and the HTML entry point. The dynamic
`type-*` and `category-*` families remain. All **562** removed selectors require
an absent class, including the sole `:has(.compare-tray)` rule. PostCSS comparison
confirmed the retained rules preserve order and declarations, and at-rule metadata
is unchanged. This establishes safety for the current source; an unpublished
future UI branch still requires its own integration review.

Frontend verification: 127 unit tests, production fixture build, and all 22 critical
desktop/mobile browser checks passed. The first browser invocation omitted the
preview flag and skipped the two production-policy checks; both were then run
explicitly and passed. The pre-existing JavaScript chunk-size warning remains.

### Spanish archive windows

The selected code combines windows only when their next archive page is identical.
It retains the earliest lower bound, latest upper bound and both loop-detection
histories. It keeps newest-window priority, the request budget, repeated-page
defences, checkpoint rules and partial-coverage reporting. No source contents,
classification, review hashes or translation keys change.

Three focused regression cases retained from PR 25 cover combined bounds and
one-read-per-shared-page behaviour, convergence during growing-feed replays, and
loop detection after a merge. The Spanish suite passes all 44 cases. Reviewed-record
validation remains valid (724 active, 8 already-stale decisions; all 20 reviewed
translations active), and the 397-case relevance benchmark has zero false positives
or false negatives. These benchmark results describe its labelled sample only.

The full pipeline suite and required PR checks are also required before merging the
selected follow-up; their final results are recorded in the PR.
